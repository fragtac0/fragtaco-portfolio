# Audit tools

Headless Chrome, driven over the DevTools protocol, for screenshots and measurements. Used for the 11 November 2026 audit and for the before and after comparison. The in-app browser pane does not animate while its window is hidden; this does.

```bash
# against the dev server (default) or any URL
BASE=http://localhost:5178 node scripts/audit/cdp.mjs scripts/audit/capture-desktop.json /tmp/out
BASE=https://fragtaco-portfolio.vercel.app node scripts/audit/cdp.mjs scripts/audit/capture-phone.json /tmp/out-phone
# contact sheet from some of the shots
scripts/audit/sheet.sh /tmp/out sheet-loader 4 480 300 load-0500 load-1200 load-2100 load-2800
```

- A steps file is a JSON list. Each step may set the screen (`size`, `dpr`, `mobile`, `touch`), emulate (`reduce`, `net`, `nocache`, `cpu`), navigate (`go`), `wait`, send input (`key`, `click`, `move`, `sweep`, `tap`, `drag`), run code in the page (`eval`, printed with its `label`) and take a screenshot (`shot`).
- Headless screenshots can lag one frame behind. Take a throwaway shot first (the `-warm` names) and use the one after it.
- Each run uses a fresh browser profile in the output folder, so nothing is cached.
- Shots whose names start with `local-` show YouTube thumbnails or book covers. Never commit those; they belong in `docs/redesign/compare/local/`, which git ignores.
- Step files named in the plan that are not here yet (`shelf.json`, `wall.json`, `history.json`, `nav.json`, `fonts.json`, `loader-throttled.json`, `shelf-cold.json`) are written by whoever runs that check, following the same pattern, and committed with the task.

Frame timing inside a step: evaluate a promise that samples `requestAnimationFrame` gaps for a few seconds and resolves with the worst gap and how many were over 20 ms.

- Headless Chrome does not advance timers or CSS transitions while the page is idle between steps (nothing animating). State that depends on a timer (a layer closing, a hint fading) must be read with an `eval` that polls inside the page (a `setInterval` promise), not after a plain `wait`.
- `page-change.json` (written by `make-page-change.mjs`, edit the generator and rerun it) measures a page change: home to work, back, and home to work again at 1440 by 900, dpr 2, CPU 4 times slower. A recorder started in the page before each click reads every animation frame gap from the click until 1 s after the path changes, and long-animation-frame entries say which script caused a long one. Needs the production build on :5180.
- `page-change.json` now reports, per change, the frames while the reveal animates (after the transition's `ready`; the first frame after it is the commit frame, R31, reported apart and not counted): `animMax`, `animOver34`, `animOver20`. `page-change-kinds.json` does the same for the linear kinds and the radial one through the debug hook (set `sessionStorage["ft:debug-change"]` to `"1"`, then `__ftChange(to, kind, origin)` runs a change of any kind; both files come from `make-page-change.mjs`).
- `transition.json`, `glass-kinds.json` and `glass-phone.json` (from `make-glass-frames.mjs`) save ten frames of a glass change each: the change is frozen at a moment of its length with the debug hook (`__hold`) and photographed, since a running transition is not painted at steady times in the audit browser. `glass-interrupt.json` starts a second change, Back, or Back then Forward in the middle of a change and reads that nothing is left over (`data-change-kind`, `data-glass`, the filter strength, the line's animations, the marks on `<html>`).
- `glass-sim.json` simulates the glass failing in Chromium: the animation cannot be listed, `CSS.registerProperty` missing and a CSS animation that never runs (all end in `data-glass-fallback`, the plain crossfade, and the change ends), an empty computed style (WebKit-like: no fallback, the animation advances) and one picture step failing (the others still work). `glass-interrupt.json` also reads the settled state (`__ftSettled`) and has a scenario in a page whose WebGL context creation is blocked.
- `rings.json` (written by `make-rings.mjs`) checks the work page's rings at 1440 by 900, 1920 by 1080, 820 by 1180, 390 by 844, 375 by 667, 568 by 320, 320 by 568, 1024 by 768 and 2560 by 1440: the arrival (delay, length, start scale of each ring), the smallest gap between any two item boxes over 40 sampled ring phases (each ring and its items' turn-back frozen at a random share of its period; must be 12 or more, 0 pairs under it), the intro inside the stack ring, pictures at three phases for four of the sizes, then hover pausing one ring (and the stack icon not growing), the stack icons (names, no tab stop), frame gaps at rest and with the pointer on a ring (1440 by 900 dpr 2 and 390 by 844 dpr 3, CPU 4 times slower) and reduced motion. The pictures come from picsum at run time; where it cannot be reached the file paints neutral generated gradients on the tiles, numbered so uprightness shows. `rings-mode.json` photographs the order mode the running build ships (rebuild with `RING_ORDER_MODE` flipped for the other).
- `ground.json` checks the work ground (R43.3) on the production build: mount time, the lazy chunk, canvas backing size against CSS size at dpr 1, 2 and 3 (must be 1.25 device pixels per CSS pixel of the screen), frame gaps with the rings turning, GPU submits per second after the first frame (0: the shader draws one frame, which is kept as a still), with the tab faked hidden (0) and on the phone profile, a resize that starts the shader again for a new frame (`framesDrawn` 1 to 2), the same canvas surviving moves between the three work addresses, no ground on `/experience`, no package fetch with reduced motion or without WebGPU, every host requested (no `shaders.com`), and `sample` steps (share of pixels darker than `#2a2826`, orange share) with and without the rings. WebGPU needs a secure context: `localhost` works in headless Chrome on this Mac (Metal) with no flags. `CHROME_FLAGS="..."` adds Chrome flags (for example `--enable-unsafe-webgpu --use-webgpu-adapter=swiftshader` for a software adapter). The `sample` step defines orange as hue 5 to 45 degrees, HSV saturation 0.45 or more and value 0.16 or more.
- `gallery.json` (written by `make-gallery.mjs`) checks the two video walls (R43.5) at 1440 by 900, 1024 by 768 (geometry only) and 390 by 844 (dpr 3, touch), on the production build: every tile's outline inside the screen and clear of the heading, the return mark and the dock (6 px of drift allowed), clicks at 12 points and at every tile centre under reduced motion (the audit warps the layout itself and does the point in polygon test), frame gaps while drifting and while hovering, a real move, click, tap, arrow keys and Enter, the page changes between the walls (`linear-right` and `linear-left`, no canvas while a change runs, the old canvas gone, Esc frees it), and a run with WebGL refused (`sessionStorage.nogl`) where all the links must still show. Picsum pictures are replaced by generated numbered gradients (the script patches `Image.src`); links are not followed, a capture listener records which tile opened.
- `shelf.json` (R44.5) also opens and closes each of three books (the first, the seventh and the last) by click and by keys at 1440 by 900 (and by click and keys at 1024 by 768, 390 by 844 and 844 by 390). Each case starts a frame recorder in the page (`window.__rec`), opens, waits 80 frames, reads the title, the lifted book's box (`data-open-box` on the canvas, in canvas pixels: left, top, right, bottom) and the note's box, closes, and reports the frame gaps for the whole run and inside the 700 ms after the open and the close (`openWindowOver20`, `closeWindowOver20`; frames over 20 ms outside those windows are cover paints that arrive late over the network). The box must lie inside the layer (top 8 px or more) and clear of the note. Arrow presses are sent as synthetic key events from `eval` (the stage listens on `window`); Enter and Escape are real key events. The fit probes read the header's bottom (`data-head-bottom`) and check the tallest spine's top is at least 8 px below it. Each open case also checks the box's top is at least 8 px under the header (`clearOfHeader`, `topToHeader`) and reads the cover texture size (`data-open-cover`) against the drawn size (box width times `data-pixel-ratio`); a flat-fit probe runs at 844 by 390.
- `experience.json` and `experience-fallback.json` (written by `make-experience.mjs`, R45.2) check the Mars map on the production build: the overview (cliff ring 72 to 84% of the smaller side, summit within 2% of the centre, first tiles painted within 300 ms of the change ending, read from `data-painted`), wheel in entering explore, panning to each edge stopping at the frame, frame gaps while panning and zooming (synthetic events from the page, rAF sampled), the keys, buttons and double click or tap, the heading fading out in explore, reduced motion, a client-side change from the dock row, and a last run at 4 times slower CPU that is reported, not a pass mark. R45.3 adds: nine markers visible, clear of each other and of their year pills and inside the screen at 1440 by 900, 390 by 844, 1024 by 768 and 1920 by 1080, none at the summit, the route's last point at the ping, the line 2 px at the overview and in explore, the draw (1.6 s) and the ping (2.4 s) read from `getAnimations()`, a click and `[` `]` flying to a moment (centred, card with its line, `aria-current`), `<s>` on IIT, Places (8 labels clear and inside the screen, route and moments hidden), the phone heading (two lines, More, the whole paragraph in the DOM), the phone sheet clear of the point and the buttons, reduced motion (no draw, a still ring, instant flights), frame gaps over the first 2.4 s of a load, and a `sample` of the picture behind the heading and caption with the words hidden (contrast is worked out from its grid by hand: ink at 72% over a cell of grey 32 is about 9 to 1). The fallback file loads the page with the canvas missing and with data saving on. Use a fresh outdir for each run: the page's response is cached for five minutes in the profile kept there.
