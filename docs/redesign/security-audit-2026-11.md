# Security audit, November 2026

The security part of the modern web pass (Task 34). Written for the owner: plain words, what was found, what was done, what is left and what only you can do. The proof is a script that anyone can run again, `scripts/audit/security.mjs`; its record is `docs/redesign/compare/web-pass/security.json` (the inventory before any change, and the proof after).

## What the site is, for a security reader

Five pages and one counter. No sign-in, no cookies, no forms, nothing a visitor types in, no content from visitors. The text comes from files in the repository. The one write the site makes is "add one" to a number in Upstash Redis, through `POST /api/page-view`. The only things from other companies that a visitor's browser loads are pictures: YouTube thumbnails (`i.ytimg.com`) and Open Library book covers (`covers.openlibrary.org`, which answers with a redirect to the Internet Archive: `archive.org` and its `ia<number>.us.archive.org` hosts). Since the fonts task (R59.1) the fonts come from the site itself, so no script, stylesheet or font comes from anyone else.

## What the inventory found (before any change)

Run on the production build with a cold browser per page, at 1440 by 900 and 390 by 844: every page, both home boxes opened (by their button and by their deep link), a book and a video opened, the wall and the shelf panned, and all 20 page changes (every page to every other page) plus Back and Forward. 4,068 requests in all.

- Requests to other origins: pictures only (`Image` type): `i.ytimg.com` 1,127, `covers.openlibrary.org` 168, `archive.org` and its subdomains 208. No script, stylesheet, font, fetch or XHR leaves the site. So the policy needs picture origins and nothing else.
- Inline scripts in the server's HTML: the home page has four (the loader's head script, Remix's scroll-restoration script, the `window.__remixContext` data and the module script that starts the app), the other pages three (without the loader's). No inline event handlers.
- Writes of HTML or script text from the browser (found by injecting `require-trusted-types-for 'script'` in report-only form into every document and collecting every report): exactly three, all when a visitor arrives at the home page by a page change, because that is when React builds the page's elements in the browser: the intro script element, its text, and the logo's inner SVG. A first load of any page, and every other page change, wrote none.
- Browser features asked for: none that need a permission. Only canvas and WebGL (2d, webgl, webgl2) and the page's own session and local storage.
- Source: two uses of `dangerouslySetInnerHTML` (the intro script and the logo), no `innerHTML`, `eval`, `document.write`, workers or other HTML sinks.

| S-2 | No content policy: a script injected into a page would run. | Same run. | The site has no user-written content, so the chance is small, but a policy turns a mistake or a compromised dependency from "runs" into "blocked and reported". | Done and enforced: scripts only with a per-response nonce (and what they load, `'strict-dynamic'`; `'self'` after them is the fallback for a browser without it, Safari before 15.4, where the page would otherwise never start), no `'unsafe-inline'` or `'unsafe-eval'`, no host list for scripts, `object-src 'none'`, `base-uri 'none'`, `frame-ancestors 'none'`, `form-action 'self'`, fonts and fetches from the site only, pictures from the site and the three picture origins above. | S-3 | Two writers of HTML into the page from the browser (the logo's inner SVG, the intro script's element). | The Trusted Types inventory: three reports, all on a page change to the home page. | The strongest defence against injection (Trusted Types) could not be switched on while they existed. | Done for the site's own code: the logo is now React elements made from the same SVG file (the markup and a screenshot of it are byte-identical to before: `scripts/audit/logo-compare.mjs`); the intro script is rendered by the server only and never again by the browser. Left alone on purpose (the spec's "not done" list): cross-origin isolation (only needed for shared memory, and it would break the picture hosts); a service worker (no offline case, and it adds a cache to get wrong); Subresource Integrity (there is no third-party script or stylesheet left); a `trusted-types` allowlist directive (it belongs to an enforced rule; with the rule only reported it does nothing, so the review's note M5 does not apply).

## The proof

`BASE=http://localhost:5180 SERVER_LOG=<server log file> node scripts/audit/security.mjs <out.json>` on the production build, with the policy as built (the nonce policy enforced, Trusted Types report-only) and nothing injected: every page at 1440 by 900 and 390 by 844, cold, both home boxes by button and deep link, a book and a video opened, the wall and the shelf panned, all 20 page changes both ways and six steps of Back and Forward. Result: no `securitypolicyviolation` event (enforced or report-only), no console error or exception, no picture or font that failed to load, no browser warning about a header, every page change settled and the loader's lock never came back on a change to the home page; every header of the set on every document and data response; two responses, two nonces, and every `<script>` of every page carries its own response's nonce; a cross-site POST to `/api/page-view` answers 403 (as does one with a foreign `Origin` and no fetch metadata) and a same-origin one 200; the report endpoint answers 204, 204, 413, 415 and 405 to its five cases; the browser's own report of a deliberate violation reached the log. Added in the fix round (R59.2c), and run on the build as shipped: the 404 page is a document too (`/nope`, `/work/nope`: status 404, every header, its own nonce, every script carries it, and Remix's default error script is gone), and three resilience cases at both sizes (`scripts/audit/security-resilience.mjs`): **a 404 first load** (the error page shows, no violation of any kind), **an element inserted at the start of `<body>` before the page's scripts run, as a browser extension does** (on `/` and `/experience`: React renders the whole root again, the page keeps all its text and elements, and Trusted Types reports 6 to 8 `Element innerHTML` writes, recorded and not failed), and **a page change whose data request answers 500** (the root error page shows, a later page change recovers the page; 4 reported writes). Enforced violations fail those cases. Against a build with Trusted Types enforced (the first shipped form) the same cases fail 13 checks: a blank document in two of them and every enforced `require-trusted-types-for` violation. Run against the build from before the change (R59.2) the header checks fail 107, as they should. The record is `security.json` (`proof`; the run before the Trusted Types change is kept as `proofBeforeReportOnlyTrustedTypes`).

What the proof cannot see: remix-serve does not apply `vercel.json` (the static files are checked by reading it), and a local build is not Vercel: whatever Vercel adds to a preview page (its toolbar's script, for one) has no nonce and will be blocked and reported. The pass's controller checks a preview deploy for both.

## Only you can do this

These are settings in other companies' dashboards or decisions about the domain; nothing here was changed.

1. **Vercel: Deployment Protection for previews.** Turn on "Standard Protection" (Vercel Authentication) for preview deployments so a preview address is not readable by anyone who guesses or is sent it. Project settings, Deployment Protection.
2. **Vercel: limits on `/api/page-view` and `/api/csp-report`.** `/api/page-view` now refuses other sites' browsers but still counts a script. `/api/csp-report` takes reports from anyone, and each one (8 KB at most) writes a log line of up to 2,000 characters. A rate limit rule for each path (Project, Firewall, a rule on the path with a rate limit per IP) would cap both: the counter if the count matters to you, and the log from being filled by a script.
3. **Upstash: the token's reach.** The site's Redis token can do whatever the database allows. Make a Redis user (Upstash console, Access Control) that may only run `INCR` and `GET` on keys that start with `portfolio:page_views:`, use its token in the Vercel environment variables, and revoke the old one. Never put the token in the repository (it is not there now).
4. **Vercel: environment variables.** `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN` should be set for Production and Preview only as needed, and the preview ones should point at a different database, so a preview cannot move the public counter.
5. **A custom domain, when you add one.** The header already carries `includeSubDomains; preload`, and `includeSubDomains` takes effect for a visitor on their first visit to the site, whether or not the domain is ever submitted for preloading: from then on, for two years, that browser refuses plain HTTP for every subdomain of the domain. A subdomain that cannot serve HTTPS (a mail or old-site host, say) becomes unreachable in that browser for two years from the visit. Put every subdomain on HTTPS before the first visit to the custom domain, or remove `includeSubDomains` from `documentHeaders`. Submit the domain at hstspreload.org only when every subdomain you will ever use is served over HTTPS; the listing is hard to undo. The `*.vercel.app` domain is already covered by Vercel.
6. **Watch the report log after the release.** Reports appear in the Vercel runtime logs as lines that start with `csp-report`. A few from browser extensions are normal, and so are Trusted Types reports (`require-trusted-types-for`, sample `Element innerHTML|<script></script>` or similar): that rule is report-only and an extension, or React after a hydration mismatch, triggers it. A steady stream of `script-src`, `img-src`, `font-src` or `connect-src` reports from a normal browser means the enforced policy blocks something it should not. To go back to report-only for the whole policy, change `Content-Security-Policy` to `Content-Security-Policy-Report-Only` in `app/lib/security-headers.server.ts` (one line in `documentHeaders`) and redeploy.
