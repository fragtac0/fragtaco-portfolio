# Round 7 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Implementers run on Sonnet at high effort. Every task review and the whole-branch review run on Opus 5.5. Fable is not used for execution.

**Goal:** Fix the faults Aditya found in the round 6 build, make every page change one slow radial reveal, replace the grounds with the Eclipse ground, rebuild the experience map to the look agreed in the previews, and give the shelves the designed spines, the rock ledge and the dot field.

**Architecture:** Assets and content first, then bugs, then what every page shares (page change, ground, home polish), then page by page. The previews under `docs/redesign/round7-preview-*/` are the visual and numeric source of truth and are ported, never imported: each sketch becomes typed, unit-tested pure modules plus thin React and canvas or WebGL code that is safe under server rendering, has a fallback and respects reduced motion.

**Tech Stack:** Remix 2.17 (Vite 6), React 18, TypeScript strict, Tailwind v4, zod, three.js 0.169, d3-contour (new, Task 16), sharp (dev), `react-icons` (Phosphor set, already installed), vitest, View Transitions API.

**Spec:** `docs/superpowers/specs/2026-11-13-round7-design.md` (section numbers below refer to it). Feedback, answers and preview notes: `docs/redesign/feedback-log.md`, "Round 7". Where this plan and the spec disagree, the spec wins; record a ruling.

## Global Constraints

- Node 22, yarn 1 through corepack: prefix every yarn command with `COREPACK_HOME="$HOME/.cache/corepack-alt"`.
- New dependencies allowed: `d3-contour` and its types (Task 16) only. `shaders` is removed in Task 7. Nothing else is added.
- No Lenis or any scroll library. No em dashes or en dashes in visible copy, titles or alt text. No serif in the interface (book spines are art and may use it).
- Never commit YouTube thumbnails, Open Library covers, or screenshots that show them (`docs/redesign/compare/local/` is git-ignored for those). Never put the owner's email address in any file, URL or request. Never write a Vercel preview address into a tracked file (its team name is built from the email).
- Never push to `main`. Never run `vercel deploy --prod`. The public link must keep showing the old site.
- Server rendering never touches `window`, `document`, WebGL, canvas or three.js. three.js only through `import("three")`.
- Animate only `transform`, `opacity`, `clip-path`, masks, small filters, canvas drawing and shader uniforms. No React state updates per animation frame. Every loop stops when its scene is not visible or the tab is hidden.
- Reduced motion (`prefers-reduced-motion: reduce`) is handled in every task that adds motion.
- Colours, type sizes, text strengths and z-index values come from `app/styles/tokens.css`; a new value used twice becomes a token.
- No file over about 350 lines after its task. Every pure function has a vitest test.
- Third-party source and assets keep their notices and a row in `docs/redesign/credits.md`.
- The previews are throwaway. Do not import from `docs/`, do not copy a preview file whole, and do not ship the Phosphor web font or the d3 bundle the previews load from a CDN.
- Commits: the repo's configured identity. Message starts with its number (`R48.1: ...`) and ends with a `Co-Authored-By` line naming the model that wrote it. PR bodies end with `🤖 Generated with [Claude Code](https://claude.com/claude-code)`.
- Each task ends green: `yarn typecheck`, `yarn lint`, `yarn test`, `yarn build`.
- Browser checks use the production build on :5180 and `scripts/audit/cdp.mjs`, never `yarn dev`. Read timer-driven state by polling inside the page. Pushing large commits: `git -c http.postBuffer=524288000 push`.
- Each part adds one line to the "Build" section of `docs/redesign/feedback-log.md` and a row per change to `docs/redesign/changes-2026-11.md` (four cells: Id | What changed | Where | Commit).
- An untracked `.claude/` directory exists in the repo: leave it, never commit it.

## Review Focus

Things the spec implies that no single task's tests exercise, most likely to bite first:

1. A slow network or a failed picture on a wall, the YouTube wall or the shelf: nothing may flash empty, pop, or stay blank; the arrival waits a bounded time, then goes ahead with placeholders.
2. A second click, a Back, or a key press in the middle of a 3.5 s page change: the change ends at once on the right page, focus lands somewhere sensible, nothing stays frozen.
3. No WebGL, a lost context, or reduced motion on any ground, wall or map: a still picture or a plain list, never a hole.
4. Small and odd screens (320 by 568, 844 by 390, 820 by 1180): the map's words, the cards, the finite YouTube wall and the spine type all stay readable and inside the screen.
5. Fonts arriving late: spines must not be painted in a fallback face and stay that way.

## How this plan is executed

One Opus controller runs the tasks in order. For each task: a fresh Sonnet implementer (effort high) with the task brief, then a fresh Opus reviewer with the diff, then fix rounds (at most five) until clean. The controller looks at the audit pictures itself before accepting a task. Each part is its own branch, stacked on the one before, pushed and opened as a PR when the part closes. Rulings continue from R51 in a new ledger at `.superpowers/sdd/2026-11-13-round7/progress.md`. The owner is away: do not stop to ask; rule, record the cost if wrong, continue.

Branch base: `r7/r47-prep` (the previews and the round 7 notes, on top of round 6).
